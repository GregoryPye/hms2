# First-draft gaps and proposed enabling work

This Stage 2G handoff proposes work for later review. It introduces no application hook, product fix, service or new executable test. Stable scenario IDs and observed findings remain in the [inventory](tools-regression-inventory.md); the [draft report](stage2g-draft-report.md) distinguishes current executed evidence from these gaps.

## HOOK-01: injectable MQTT client creation

Boundary: `app/Listeners/Tools/NotifyNhToolsSubscriber.php::poll` directly constructs `karpy47\PhpMqttClient\MQTTClient`. The subscriber is queued and handles NewBooking, BookingChanged and BookingCancelled. Existing tests prove registration, payload/channel serialization and a queued-wrapper serialize/rehydrate round-trip without calling its handler. They do not execute the notifier or real MQTT.

Proposed smallest Stage 3 change: inject a small client factory through the container and replace only the direct construction with a factory call. The production factory must still create the same client with the configured host/port. Prefer an ordinary typed recording/mock client through that factory; add a narrow adapter only if the library type cannot safely be doubled. Keep connection ID `hms`, topic `nh/bookings/poll`, plain tool-name payload, success-dependent publish/disconnect, unconditional final close on the ordinary path, event registrations and queue policy unchanged. Preserve existing failure/exception behavior; adding retries or stronger cleanup semantics would be a separate behavior change. No new production env setting is necessary.

Stage 3 evidence should show default factory binding and unchanged invocation arguments/control flow with recording clients, plus the existing draft's owning backend checks. The adapter must never connect during construction or bootstrap. Do not use class alias replacement, reflection into private behavior or library monkeypatching. Review the enabling change separately before adding the deferred business cases.

Stage 4 cases unlocked (PHP-18/HOOK-01): dispatch each event through the real registered queued-handler boundary into a recording factory/client; verify correct tool identity including cancelled records, exact connect/publish/disconnect/close order and arguments, failed-connect branch, thrown-client behavior, no unexpected transport, and finite test timeout. Run one explicitly scoped serialized/reconstituted queued job against disposable persistence; never start a general worker/scheduler. Pure protocol decisions use no network; optional real-library protocol compatibility needs a separately approved disposable broker and internal-only bridge. A recording client proves calls, not wire delivery.

## HOOK-02: local websocket delivery is a service gap

No new application hook is presumed. Existing Laravel broadcast bindings can record contracts; current browser Echo subscriptions are local recordings. The missing evidence is actual event dispatch/queue/broadcast delivery to an actual local browser connection, including ordering and duplicates.

Before implementation select a pinned public Pusher-compatible local server and compatible browser configuration. Bind only internal test aliases; no host ports, remote Pusher endpoint, production app IDs/keys, public DNS or forwarding. Use wholly synthetic credentials. Keep external HTTP/websocket denial independent and allow only the exact local service path. Review build/license/resource requirements and fail closed if the service cannot start. Any product configuration seam genuinely required by this investigation must be recorded and reviewed separately; do not assume credentials solve the gap.

Stage 4 evidence (PHP-15/18, UI-03, WEB-02/HOOK-02): emit a real booking event through one scoped queue/broadcast path, consume in Chromium, verify payload and persisted identity, API-before-event/event-before-API behavior, duplicate suppression and current-user counts. Confirm subscription cleanup, rejection of a foreign/external endpoint and complete service teardown in both fresh/reordered cycles. Existing counter and before/after-event defects must remain visible until fixed; the live service must not conceal them.
